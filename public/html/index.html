Entity Relationship & Structural Architecture

Complete architectural map of the Question Bank, detailing taxonomy hierarchies, question models, test engines, and evaluation pipelines.

1. Hierarchical Taxonomy System

Provides the multi-tier taxonomy classification. Content is grouped by Target (e.g. Academic HSC, Admission BUET, Job BCS), then split into flexible Containers & ContainerItems or direct Subjects & Chapters.

qbTargets (Target Group: Academic | Admission | Job)
  ├── qbContainers (e.g. Board Questions, Model Tests, Books)
  │    └── qbContainerItems (e.g. Dhaka Board 2023, Test Paper 1)
  └── qbSubjects (e.g. Physics 1st Paper, Higher Math)
      └── qbChapters (e.g. Vector, Mechanics)
          └── qbTopics (Self-referential recursive Tree)

2. Polymorphic Question Engine

Supports both multiple choice (MCQ with options and correctness) and composite written questions (sub-parts with marks, markdown, and KaTeX math formatting).

qbQuestions (qType: mcq | written, status: published)
  ├── qbQuestionOptions (For MCQ: optionText, isCorrect)
  ├── qbQuestionParts (For Written: partText, answer, marks)
  ├── qbQuestionSources ── qbSources (Year, Unit, Board)
  └── qbQuestionChapters ── qbChapters

3. Curated Exam Sheets

Pre-compiled test sheets attached to specific ContainerItems (e.g. Board Papers) or Chapters. Designed for instant practice with timer, negative marking, and ordered question sequences.

qbExamSheets (durationMinutes, totalMarks, negativeMarks)
  ├── references qbContainerItems (Exam collections)
  ├── references qbChapters (Chapter-specific test)
  └── ── qbExamSheetQuestions ── qbQuestions

4. Dynamic Exams & Grading Pipeline

Users generate custom exams with custom subject/topic filters. Submissions support instant MCQ auto-evaluation and written submission handling with annotated image uploads.

qbCustomExams (Created by User, filters, config JSON)
  ├── qbCustomExamQuestions (Selected Question IDs)
  └── qbCustomExamSubmissions (Score, time, auto/manual)
      └── qbCustomExamWrittenSubmissions (Images, marks, evaluator feedback)

Data Processing Pipelines & Service Lifecycles

Deep dive into the background services, counter aggregation, scrapers synchronization, and exam execution workflows.

Denormalized Rollup Engine

services/qb-count.service.ts

Maintains high-performance query latency for millions of questions by updating precomputed counts up the hierarchy:

  1. 1. qb_topics.question_count
  2. 2. qb_sources.question_count
  3. 3. qb_chapters.question_count
  4. 4. qb_subjects.question_count
  5. 5. qb_exam_sheets.question_count
  6. 6. qb_container_items.question_count
  7. 7. qb_targets (sum of subjects + containers)

Scraper Sync & Ingestion

db/sync-scraped-qb.ts

Automated ingestion pipelines transform raw curriculum JSON and scraped test papers into standard Drizzle entities:

  • Math/KaTeX normalization
  • Deduplication by slug & hash
  • Automatic source extraction (Year, Board)
  • Recursive topic hierarchy building

Exam & Evaluation Cycle

routes/qb.route.ts

Handles test creation, timed answer submission, real-time grading, and teacher evaluation:

  • Generate Random/Filtered Custom Exam
  • Auto-Evaluation with negative mark deduction
  • Written Script OCR / Image Canvas Review
  • Teacher feedback & final score publishing

Question Bank (QB) Technical Architecture Document

Complete architectural documentation for apps/api/src/db/schema/qb.ts and related modules.

Overview

The Question Bank (QB) in Paws Academy is a multi-tenant, high-throughput educational database subsystem designed to store, classify, search, practice, and evaluate academic and competitive exam questions for Bangladesh's education landscape (SSC, HSC, University Admissions like BUET/Medical/DU, BCS, and Job exams).

Database Design Principles

  • Polymorphic Content Delivery: Unified storage for both Single/Multiple Choice Questions (mcq) and Descriptive/Creative Written Questions (written) using sub-options and sub-parts.
  • Dual Hierarchy Pathways:
    • Standard Curriculum Tree: Target → Subject → Chapter → Topic (recursive tree).
    • Collection / Exam Set Tree: Target → Container → ContainerItem → ExamSheet.
  • Denormalized Performance Caching: Pre-calculated question_count, subject_count, and exam_sheet_count maintained via the recalculateAllCounts() engine to avoid recursive COUNT(*) queries on massive production tables.
  • Multi-Dimensional Tagging: Many-to-many associations between Questions, Chapters, and Historical Exam Sources (qb_question_sources, qb_chapter_sources).
  • Comprehensive Assessment Engine: Supports timed exam generation, student answer persistence, negative marking calculation, and manual evaluation workflows with written image uploads.
